## Q1：节点和状态是什么关系？为什么把状态写成类？

**问题**：节点和状态之间是怎样的关系？类为什么和状态契合、要把状态做成类？类像名词、方法像动词？

**回答**：
- 节点 = 动词（动作/逻辑），状态 = 名词（数据/东西）。
- 关系：节点是操作者，状态是被操作对象。节点读 `state.xxx` → 计算 → `return dict` 写回。
- 类 = 名词 + 动词统一体：属性（字段）描述"是什么"，方法描述"能干什么"。
- 状态天然是"一个东西带一堆属性"，类恰好是描述"东西 + 属性"的最优工具（需求匹配，非巧合）。
- 状态类被刻意做成"纯名词"（贫血模型：只有字段、没有自定义方法），动作交给节点函数。

## Q2：什么是枚举值？InquiryPhase 依据什么编写、取值哪里？

**问题**：什么是枚举值？InquiryPhase 枚举值依据什么编写、取值哪些地方？

**回答**：
- 枚举 = 把"有限的固定选项"打包成"有名字的常量"，只能选、不能乱写，写错立刻报错。
- `class InquiryPhase(str, Enum)` 是混合枚举：既有枚举约束，成员本身又是字符串（值如 `"CLARIFY"`）。
- 依据：问诊业务的流程图，每个阶段一个值（CLARIFY / GRAPH_QUERY / SYMPTOM_CONFIRM / COMPLICATION_CHECK / CONCLUDE / HANDOFF / END）。
- 取值 3 处：① state.py 初始默认值；② 节点 `return {"phase": ...}` 写；③ 路由函数 `if state.phase == ...` 读。
- 细节：`END = "__end__"` 对齐 LangGraph 内置结束标记；`COMPLICATION_CHECK` 定义了但当前未使用。

## Q3：为什么要写 InquiryState 主状态对象（黑板）？

**问题**：为什么要写 InquiryState？把 4 个类组合起来的"黑板"怎么通俗理解？

**回答**：
- 原因：节点是独立函数，局部变量用完即销毁，彼此无法共享数据。
- LangGraph 机制：节点接收 state，`return dict` 自动合并回 state，再传给下一节点。
- 通俗：InquiryState = 问诊现场的一块公共黑板；9 个节点 = 围着黑板干活的人，动作是"看黑板 → 做动作 → 写黑板"。
- 4 个类（InquiryPhase / CandidateDisease / PatientContext / InquiryHandoffPayload）都是需跨节点传递的数据，塞进黑板统一传递。
- 不用全局变量（多用户会互相污染）也不用数据库（每一步都读写太慢）。
